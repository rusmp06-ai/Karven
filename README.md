# Karven CRM

CRM смешанного междугороднего таксопарка: рейсы, клиенты, бронирования, частичные оплаты, водители, автомобили, назначения, завершение рейсов, возвраты, расходы, расчёты с водителями и личные учётные записи.


## Дизайн и демонстрация

Для автономного просмотра скачайте `karven-html.zip`, распакуйте и откройте единственный файл `karven-demo.html`. Он содержит стили, примеры и переключение разделов/рейсов, не требует Node.js, сервера или сети. Формы доступны для просмотра, сохранение и банковские операции отключены. Это отдельный снимок интерфейса для демонстрации, а не рабочая CRM с базой.


Интерфейс реализован по согласованной концепции Karven: тёмное боковое меню, глобальный поиск, показатели дня, компактное расписание, интерактивная карточка рейса, индикатор вместимости, пассажиры и оплаты. На телефоне меню открывается отдельной кнопкой, а выбранный рейс располагается под расписанием.

Для просмотра заполненного интерфейса запустите приложение и откройте путь `/demo` на том же адресе, который напечатан терминалом. Это публичная демонстрация на фиксированных примерах: база не используется и не заполняется, сохранение форм заблокировано. Для рабочих данных откройте `/` и войдите своей учётной записью. Демонстрация не требует настройки пароля или внешних сервисов.

В рабочем режиме показатели не выдумываются: рейсы и пассажиры считаются по сегодняшней дате Бишкека, «Получено сегодня» — по фактическим датам платежей за вычетом возвратов, долги — по подтверждённым заказам. Разные валюты не складываются. Индикатор мест показывает заполненность; закрепление конкретных номеров мест не реализовано.

Новая навигация:

- **Диспетчерская:** выберите строку рейса; справа откроются водитель, места, пассажиры, суммы. «Открыть рейс» даёт доступ к назначениям, завершению и отмене. «Создать рейс» открывает отдельное окно.
- **Бронирования:** карточки заказов и новая бронь; переход из выбранного рейса автоматически задаёт рейс.
- **Водители / Автомобили:** отдельные разделы с существующими рабочими формами.
- **Клиенты:** список контактов из заказов с переходом к истории поездок; это ещё не отдельный редактор клиентской базы.
- **Финансы:** расходы, возвраты, утверждения и выплаты.
- **Задачи:** актуальные вопросы из данных парка (долги, документы, назначения, отметки), без отдельного редактора поручений.
- **Отчёты:** сводки по направлениям и валютам.
- **Настройки:** учётные записи и журнал действий, только для владельца.

Снимки нового интерфейса: `docs/design-desktop.png` и `docs/design-mobile.png`. Файл `preview.html` открывается без установки и показывает эти снимки; для работы с кнопками запускайте приложение.

## Запуск

Node.js 22 или 24, npm. Используйте существующий checkout; отдельный worktree не нужен.

```sh
npm ci
cp .env.example .env.local
```

Укажите в `.env.local` `CRM_ADMIN_USER` (латиница, 3–64 символа) и надёжный `CRM_ADMIN_PASSWORD` (12–128 символов). Эти значения **только создают первого владельца**, если в БД ещё нет пользователей. Они больше не являются способом входа в обход базы. Не перезаписывайте существующий `.env.local`. При отсутствии пользователей и начальных настроек войти невозможно; задайте их и перезапустите приложение.

```sh
npm run dev
```

На порту 3000 откроется форма входа. Владелец создаёт сотрудников в разделе «Сотрудники»: задаёт логин, начальный пароль и роль. Учётная запись водителя обязательно связывается с карточкой водителя. Передавайте начальные пароли сотрудникам безопасным способом. Владелец может сбросить пароль и заблокировать сотрудника, при этом его сессии завершаются. Себя заблокировать нельзя.

Пароли хранятся как scrypt-хеши с индивидуальной солью. В БД хранится только SHA-256-хеш случайного токена сессии; HttpOnly-cookie действует 8 часов, SameSite=Lax. После 5 неудачных попыток вход для логина ограничивается на 15 минут. Для удалённого доступа обязателен HTTPS и `CRM_COOKIE_SECURE=true`; локально по HTTP можно использовать `false`. Без явной настройки Secure определяется по HTTPS-протоколу доверенного reverse proxy. Не предоставляйте клиентам возможность подменить forwarded-заголовки на прокси.

## Права

| Возможность | Владелец | Диспетчер | Водитель |
|---|---|---|---|
| Рейсы и пассажиры | Все | Все | Только назначенные рейсы и подтверждённые пассажиры |
| Бронирования, оплаты, отмены | Да | Да | Только просмотр своих |
| Водители, машины, назначения | Да | Да | Нет |
| Посадка и неявка | Да | Да | Только свой рейс |
| Учётные записи, блокировки, сброс пароля | Да | Нет | Нет |
| Журнал действий | Да | Нет | Нет |

Права проверяются на сервере. Внутренние заметки не выдаются водителю. Журнал включает автора новых операций; старые события версии 0.1 остаются без автора. Роль существующей учётной записи пока не редактируется; можно заблокировать старую запись и создать новую с другим логином (одна карточка водителя связывается с одной учётной записью).

## Назначения

1. Добавьте водителя: штатный/привлечённый, контакты, статус, номер и срок удостоверения.
2. Добавьте машину: госномер, модель, пассажирская вместимость без водителя, владелец, принадлежность и статус.
3. Создайте рейс; исходное плановое окончание — отправление + 6 часов.
4. Откройте «Назначить или заменить», выберите ресурсы и уточните окончание.

Нельзя назначить недоступные ресурсы, удостоверение с недостаточным сроком, машину меньше уже проданного числа мест или ресурсы, занятые в пересекающемся рейсе. Интервалы полуоткрытые: следующий рейс может начинаться точно в момент окончания предыдущего, запас на возвращение/отдых нужно включать в плановое окончание. После назначения вместимость рейса равна вместимости автомобиля. Менять назначение можно только до отправления. Статус и вместимость ресурса нельзя изменить так, чтобы нарушить предстоящие назначения. Явно снять назначение без замены пока нельзя.

## Данные и проверки

```sh
npm test
npm run typecheck
npm run build
npm start
```

71 автоматический тест проверяет денежные расчёты, конкурентные бронирования/назначения/оплаты/возвраты/выплаты, повторные запросы, роли, сессии, блокировки, миграции и сохранение данных на диске.

```sh
npm run test:e2e
# Проверка уже собранной версии (после npm run build):
E2E_PRODUCTION=true npm run test:e2e
```

Браузерные тесты используют Chromium (`/usr/bin/chromium`, либо `CHROMIUM_PATH`), отдельную временную БД и сервер на порту 3100. Пять сценариев проверяют дизайн/демонстрацию, вход, ресурсы, назначения, быстрое бронирование всей машины, пассажиров, редактирование, фильтры, перенос, изменение состава, посадку/неявку, отмену рейса, сотрудников, кабинеты, возврат, расходы, завершение рейса, утверждение расчёта и выплаты. Тестовая заготовка прошедшего отправления создаётся только в отдельной временной БД; обычный запуск данные не заполняет. Не запускайте dev и build одновременно: они используют `.next`.

PGlite хранит данные в `data/postgres` (или `DATABASE_DIR`). Только **один процесс приложения** может открыть эту папку. Остановите dev-сервер перед `npm start`. Для копирования БД остановите приложение и скопируйте всю папку; восстановление проверяется отдельно. Миграция 2 сохраняет старые рейсы и присваивает им плановое окончание через 6 часов; уточните эти времена до назначения.

Деньги хранятся в целых сотых долях валюты, оплата отдельными записями. Переплата запрещена. Отменить неоплаченную бронь может диспетчер; отмену с возвратом выполняет владелец. Завершённый рейс отменять нельзя. Даты хранятся как `timestamptz`: ввод в часовом поясе браузера, отображение и фильтр в Asia/Bishkek.



## Диспетчерская и карточка заказа

Расписание фильтруется по дате (Бишкек), направлению, статусу и тексту. «Сегодня» выбирает местную дату; «Сбросить» снимает фильтры. Кнопка «Забронировать» в рейсе сразу выбирает его в форме и показывает его заказы. Поиск по заказам учитывает заказчика, пассажиров, телефоны и адреса.

В заказе отдельно сохраняются заказчик и список пассажиров. По умолчанию заказчик — первый пассажир; снимите флажок, если бронируете для другого человека. Укажите имя каждого пассажира; дополнительные телефоны необязательны. Адреса посадки/высадки, багаж, детские кресла, источник заявки и внутренний комментарий записываются отдельными полями. Водитель видит операционные данные только своего рейса, без внутренних комментариев и источника заявки.

Два типа заказа:

- Отдельные места: число пассажиров равно числу резервируемых мест.
- Вся машина: число пассажиров задаётся отдельно, но бронь занимает всю вместимость. Нужен рейс без других подтверждённых заказов. Замена автомобиля сохраняет эксклюзивность и проверяет фактическое число пассажиров.

Контакты и детали можно изменить из карточки активного заказа до завершения рейса. Это не меняет стоимость и число пассажиров/мест. Контакты являются снимком заказа; редактирование одного заказа не меняет остальные заказы того же клиента. Изменение количества пассажиров и перенос между рейсами выполняются отдельными действиями с причиной, не меняя согласованную общую цену.

Миграция 4 сохраняет старые цены, места и оплаты, добавляет детали и переносит существующий контакт в карточку. Имена остальных пассажиров старой групповой брони остаются неизвестными; интерфейс показывает это явно. Для редактирования такой брони потребуется заполнить всех пассажиров.

## Завершение и финансы

В карточке рейса — «Завершить рейс». Владелец или диспетчер подтверждает фактическое окончание после отправления, назначения ресурсов и обработки всех пассажиров (посадка или неявка). Статус закрывает новые брони и замену водителя/машины; существующие долги пассажиров остаются и могут быть оплачены позже. Автоматического списания долгов нет.

Владелец оформляет частичный возврат из карточки брони. Он уменьшает стоимость поездки и полученную оплату на одну сумму, не повышая долг клиента. Исходная цена и платежи остаются в базе, возврат — отдельная запись с причиной. Это согласованное уменьшение стоимости, а не временный возврат предоплаты с последующим повторным взысканием. Сумма не может превышать оплаты за вычетом прошлых возвратов. «Отменить с возвратом» атомарно записывает возврат всей оставшейся оплаты, отменяет бронь и освобождает места. Отмена брони завершённого рейса запрещена, но частичный возврат с уменьшением стоимости доступен и после завершения.

В разделе «Финансы» выберите рейс. Владелец и диспетчер учитывают топливо, дороги, стоянки и прочие расходы, указывая плательщика — парк или водитель. Расход водителя возмещается дополнительно к вознаграждению. До утверждения расчёта владелец может аннулировать ошибочный расход с причиной; запись остаётся в истории. Заменить водителя с активными расходами прежнего водителя нельзя — сначала требуется их корректное аннулирование и разрешение вопроса возмещения.

После завершения или отмены рейса с назначенным водителем владелец задаёт фиксированное вознаграждение (допустим 0) и основание суммы, затем утверждает расчёт. Он фиксирует водителя, вознаграждение и возмещение его расходов. Добавление и аннулирование расходов блокируется. Выплаты записываются частями в пределах остатка. Это учёт фактически переданных денег, приложение не выполняет банковский перевод. Водитель видит только собственные расходы, вознаграждение, выплаты и остаток; финансовые показатели парка ему не передаются.

- Результат по начислениям = стоимость подтверждённых поездок после возвратов − все расходы − утверждённое вознаграждение. До утверждения результат не показывается как окончательный.
- Денежный итог парка = записанные оплаты пассажиров − возвраты − расходы, оплаченные парком − выплаты водителю (вознаграждение и возмещение). Сбор денег водителем с последующей сдачей парку отдельным процессом пока не моделируется.
- Валюта каждой операции наследуется от рейса; суммы разных валют не объединяются.
- Платежи, возвраты, расходы, утверждения и выплаты защищены ключом повторного запроса. Один ключ с другими данными отклоняется. Ключ формы меняется только после успешного ответа.

Миграция 3 добавляет финансовые таблицы и фактическое время завершения, сохраняет существующие данные. Ранее завершённым рейсам фактическое время не выдумывается. Перед обновлением остановите приложение и сохраните копию папки базы.


## Управление поездкой

В карточке заказа:

- «Перенести в другой рейс» — только до отправления, между запланированными рейсами одного направления и валюты. Проверяются свободные места, для всей машины нужен свободный автомобиль. Заказ сохраняет ID, цену, оплаты, возвраты, контакты и адреса; проверьте адреса после переноса. В финансовых отчётах операции заказа относятся к его текущему рейсу; история содержит прежний и новый рейс.
- «Изменить число пассажиров» — до отправления, с полным списком пассажиров и причиной. Согласованная общая цена не меняется. Детских кресел не может быть больше пассажиров. Эксклюзивный заказ продолжает резервировать весь автомобиль.
- «Посадка и неявка» — индивидуальные отметки. Посадка открывается за 2 часа до отправления, неявка — после времени отправления. Водитель отмечает только пассажиров своего рейса. Неявка не отменяет заказ, не освобождает места задним числом и не списывает долг.
- Исправить уже поставленную отметку может владелец или диспетчер с обязательной причиной. Возврат к ожиданию снимает отметку, но сохраняет событие в истории. После закрытия рейса отметки не редактируются.
- «История заказа» — последние 30 событий с автором и причиной; полный журнал хранится в базе. История доступна владельцу и диспетчеру, водитель её не получает.

После отметок нельзя менять состав/карточку заказа, переносить/отменять его или заменять ресурсы рейса без предварительного исправления отметок менеджером. Отправившиеся заказы не переносятся даже после исправления.

В карточке рейса есть «Отменить рейс». Подтверждение отменяет все активные брони, записывает возвраты оставшихся оплат и освобождает ресурсы одной транзакцией. Завершённый рейс отменить нельзя; при наличии пассажирских отметок сначала необходима проверка и исправление. Диспетчер отменяет только рейсы без оставшихся оплат; платный возврат доступен владельцу. Перед сохранением нужно подтвердить фактические возвраты — приложение не отправляет деньги автоматически. Уже выполненные возвраты не повторяются.

Расходы при отмене остаются в учёте. Для отменённого рейса с водителем можно утвердить возмещение его расходов и явно согласованную компенсацию (в том числе 0); это не автоматический штраф/комиссия. Выплаты записываются обычным способом. Для отменённого рейса без водителя результат равен оставшимся расходам со знаком минус.

Миграция 5 добавляет статус отмены и таблицу отметок. Старые завершённые рейсы не меняются, отсутствующие старые отметки не выдумываются.

## Ограничения

Это локальный прототип. Перед реальной эксплуатацией нужны отдельный сервер PostgreSQL с проверками на нескольких соединениях, HTTPS, автоматические резервные копии с проверкой восстановления, мониторинг и проверка инфраструктуры. Пока отсутствуют загрузка документов, интеграции, самостоятельная смена пароля, автоматические комиссии, корректировка уже утверждённого расчёта и сторнирование выплат. Повтор запроса с тем же ключом не дублирует финансовую операцию; две отдельно заполненные формы с разными ключами считаются разными операциями.

[Архитектура](docs/architecture.md).

### Связанный рабочий цикл

В форме новой брони можно записать фактически полученную предоплату и способ оплаты. Бронь, места, платёж и журнал сохраняются одной транзакцией; предоплата выше цены отклоняется. Создание рейса и брони защищено от повторной отправки того же запроса. Миграция 6 добавляет ключи запросов и сохраняет существующие данные.

Новый рейс выбирается в диспетчерской, новый заказ показывается в списке бронирований. Кнопка «К расчёту рейса» в карточке открывает финансы именно этого рейса. Раздел, дата, выбранный рейс и заказ сохраняются в адресной строке при перезагрузке; имена, телефоны и поисковая строка туда не записываются.

`e2e/cycle.spec.ts` создаёт рейс через интерфейс, назначает ресурсы, бронирует с предоплатой, проверяет перезагрузку, посадку, завершение, расчёт и выплату. Тест дожидается реального времени отправления в отдельной временной базе. HTML-файл остаётся автономной демонстрацией дизайна; рабочие операции выполняются в Next.js-приложении.

### Клиенты и задачи

Раздел «Клиенты» открывает карточку заказчика: заказы и поездки, полученные суммы и задолженность отдельно по валютам, операции оплат и возвратов, внутренние заметки с автором и временем. История связывается по ID клиента, а данные старых заказов сохраняются отдельно. Карточка клиента восстанавливается после перезагрузки. «Повторное бронирование» подставляет имя и телефон; рейс, пассажиров и актуальную цену нужно проверить в форме нового заказа.

В «Задачах» владелец и диспетчер создают поручения с описанием, действующим ответственным, сроком и необязательной привязкой к клиенту и рейсу. Статусы: новая, в работе, выполнена, отменена. Есть фильтры по статусу, своим и просроченным задачам, поиск и переход к связанной карточке. Просроченными считаются только незакрытые задачи; уведомления отображаются внутри приложения. Ввод срока использует часовой пояс устройства, отображение — Бишкек (UTC+6).

Заметки и задачи сохраняются в локальной базе; водитель не получает эти данные и не может управлять ими. Изменения задач записываются в журнал; устаревшая версия формы не перезаписывает изменения коллеги. Миграция 7 сохраняет существующие данные и добавляет таблицы `client_notes`, `work_tasks`. Встроенный HTML-просмотр остаётся демонстрацией дизайна.

### Контроль рейса

В карточке рейса владелец и диспетчер видят сводку пассажиров, свободных мест, посадки, неявки, оплат и открытых задач. Резерв всей машины учитывается отдельно от фактического числа пассажиров; отменённые заказы не входят в сводку.

Проверки перед отправлением показывают назначения, доступность водителя и машины, действительность удостоверения на дату рейса и незаполненные адреса. Перед закрытием показаны условия завершения: назначенные ресурсы, наступившее время отправления, отметки всех пассажиров. Долги и задачи сохраняются после завершения, как и прежде. Фактическое окончание поездки подтверждает сотрудник.

Список пассажиров содержит адреса, багаж, детские кресла, телефоны и остаток оплаты по заказу. Фильтры выделяют долги, ожидающих отметки и отсутствующие адреса. Кнопки открывают соответствующую форму посадки или оплаты в карточке заказа. Создание и изменение привязанных задач доступны прямо в рейсе. Открытая карточка восстанавливается после перезагрузки; доступ проверяется по рейсам текущего пользователя. Новых таблиц или внешних сервисов этот экран не требует.
