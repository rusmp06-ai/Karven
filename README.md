# KARVEN CRM

CRM смешанного междугороднего таксопарка: рейсы, пассажиры, бронирования, оплаты, водители и автомобили, расходы, возвраты, смены менеджеров и контроль владельца.

Порядок работы, отмены, касса, Telegram, отчёты и ограничения: **[руководство владельца и менеджера](docs/owner-manager-guide-ru.md)**.

## Запуск

Node.js 24, npm. Не перезаписывайте существующий `.env.local`.

```sh
npm ci
cp .env.example .env.local  # только для новой установки
npm run dev
```

`CRM_ADMIN_USER` и `CRM_ADMIN_PASSWORD` создают первого владельца только в пустой базе. Это не обход авторизации существующей установки. Пароль — 12–128 символов, логин — латиница, цифры и `_.-`, 3–64 символа. Откройте `/`, войдите владельцем и создайте отдельные аккаунты менеджеров.

Без `DATABASE_URL` используется постоянная PGlite в `DATABASE_DIR` или `data/postgres`. Одну папку нельзя открывать двумя процессами. С `DATABASE_URL` используется серверная PostgreSQL в закрытой схеме `karven`; данные `public` не затрагиваются.

```sh
npm run db:migrate  # подготовить серверную PostgreSQL
npm run db:check
```

Для Supabase SQL Editor есть полный атомарный установщик [docs/supabase-netlify.sql](docs/supabase-netlify.sql). Текущая схема — **10**; установленная схема 9 обновляется аддитивно при первом запросе новой версии под блокировкой и транзакцией. Новую установку подготавливает миграция. Старые копии 8/9 поддерживаются. Рабочие данные не заполняются демонстрационными примерами.

## Роли

| Возможность | Владелец | Менеджер (`dispatcher`) | Водитель |
|---|---|---|---|
| Просмотр рейсов и броней | Отдельная консоль | Диспетчерская | Назначенные рейсы и активные пассажиры |
| Брони, оплаты, отмены, возвраты | Наблюдение | Полный цикл | Нет |
| Ресурсы, назначения, завершение, расходы и выплаты | Наблюдение | Да | Собственный расчёт, просмотр |
| Посадка и неявка | Наблюдение | Да, исправления с причиной | Только собственный рейс |
| Смена и передача наличных | Контроль | Собственная смена | Нет |
| Аккаунты, блокировки и сброс пароля | Да | Нет | Нет |
| Telegram, реквизиты, документы и полный журнал | Да | Нет | Нет |
| Настройки парка и тарифы | Через менеджера | Да | Нет |

Публичные серверные действия проверяют роль до выполнения операции. Скрытие кнопок не является защитой. Внутренние заметки и финансовые показатели парка не передаются водителю. Через приложение создаются менеджеры и водители; менять существующую роль нельзя.

Пароли — scrypt с индивидуальной солью. В базе хранится SHA-256 токена сессии, HttpOnly-cookie действует 8 часов, SameSite=Lax. После 5 ошибок действует ограничение логина на 15 минут; есть общий и источниковый лимиты, старые попытки очищаются. Блокировка или сброс пароля завершает сессии. Для удалённого доступа нужен HTTPS и `CRM_COOKIE_SECURE=true`.

## Основные правила

- Деньги хранятся целыми сотыми долями валюты. Валюты не складываются и не конвертируются автоматически. CRM записывает переданные деньги, не выполняет банковские переводы.
- Бронирование проверяет места в транзакции. «Вся машина» резервирует полную вместимость, отдельно от числа пассажиров. Назначение машины с другой вместимостью требует подтверждения и не может уменьшить места ниже проданных.
- Рейсы одного водителя или автомобиля не пересекаются. Проверяются доступность, документы и время. Переоценка маршрута не меняет уже согласованную цену брони.
- Отмена освобождает места, сохраняет причину/инициатора/удержание и создаёт обязательство. Фактический возврат — отдельная запись, допустим частями. Отмена рейса не выдаёт деньги автоматически.
- Редактирование карточки, состава и переноса проверяет версию брони. Повтор запроса с одним ключом не дублирует деньги; тот же ключ с другим содержимым отклоняется. Ошибка сохранения не стирает черновик.
- Завершение требует назначенных ресурсов и отметок каждого пассажира. Посадка доступна за 2 часа до отправления, неявка — после отправления. Исправления требуют причины. Завершённые поездки не отменяются.
- Менеджер фиксирует расходы парка/водителя, утверждает вознаграждение после завершения или отмены и записывает фактические выплаты. Возмещение водительских расходов не списывается повторно как расход парка при подсчёте движения денег.
- Для наличных нужна открытая смена. Передача меняет остатки после подтверждения получателя. Закрытие фиксирует пересчёт, расхождение и объяснение; новая смена переносит заявленный фактический остаток. Корректировки видны владельцу отдельно.
- Даты хранятся как `timestamptz`; ввод — часовой пояс устройства, отображение и отчётные периоды — Asia/Bishkek.

## Отчётность и архив

Владелец сохраняет отдельный снимок периода: реквизиты, реестр денежных операций, исполнители, обязательства возврата, закрытые смены и корректировки. PDF поддерживает кириллицу, включает идентификатор, версию, контрольную сумму и места подписей. CSV выгружает те же зафиксированные операции; текст защищён от формул электронных таблиц. Документ можно поставить в очередь отправки PDF через Telegram. Исправленный отчёт создаётся новой версией со ссылкой на предыдущий.

**Это управленческий отчёт, не налоговая декларация.** Правовая форма зависит от страны, налогового режима и модели перевозчик/посредник. Заполнение реквизитов не заменяет первичные документы и проверку бухгалтером.

Журнал и оригиналы документов сохраняются в отдельной схеме `karven_archive` и переживают восстановление рабочих таблиц на том же сервере. Рабочая копия и экспорт архива контроля скачиваются отдельно. Для переноса всей установки нужен также полный дамп архивной схемы. Администратор PostgreSQL остаётся привилегированным; SHA-256 не является электронной подписью.

Резервная копия схемы 10 включает 26 рабочих таблиц и проходит пробное восстановление с проверкой связей и сумм. Сессии, попытки входа, настройки и очереди Telegram исключены. В панели владельца доступны создание и скачивание; восстановление — техническая процедура сервиса `createBackups`, не операция менеджера и не публичное серверное действие. Сервис проверяет текущий пароль владельца и явное подтверждение, создаёт страховочную копию, заменяет данные атомарно и закрывает сессии. Автоматические внешние резервные копии не подключены.

## Telegram и Netlify

Владелец настраивает токен и чат в приложении. На Netlify нужен постоянный `CRM_TELEGRAM_KEY`: 64 шестнадцатеричных символа. Ключ шифрует токен и не равен токену BotFather. Серверу нужен доступ к `api.telegram.org`.

Очереди создаются вместе с бизнес-операциями. Ошибка доставки не отменяет бронь или возврат. Новые брони, отмены, фактические возвраты и отмены рейсов уведомляются отдельно. Сетевой обрыв оставляет статус неизвестным без автоматического дублирования; ручной повтор требует владельца и подтверждения. Смена подключения отменяет старую неотправленную очередь. В тестах используется подставной транспорт без реальных сообщений.

[Настройка Netlify](docs/netlify-setup-ru.md). Для Supabase используется **Session pooler, порт 5432**. Transaction pooler 6543 не поддерживается общей блокировкой запросов. Проверка TLS включена; доверенный CA Supabase встроен, возможны серверные `PGSSLROOTCERT_PEM`/`PGSSLROOTCERT`. Не отключайте проверку сертификата.

Serverless-запрос удерживает одно соединение под общей блокировкой; неуспешные претенденты освобождают соединения, чтобы не исчерпать лимит пула. Scheduled Function обрабатывает очередь Telegram. Бесплатные лимиты Netlify/Supabase действуют независимо от кода; высокая нагрузка и холодный запуск могут влиять на время ответа.

## Дизайн, демонстрация и установка

`/demo` — публичный интерфейс на фиксированных примерах без доступа к базе и сохранения. Он показывает диспетчерскую менеджера; рабочая панель владельца доступна после входа. Тёмное меню, голубые акценты, карточки заказов/клиентов и финансовый журнал соответствуют согласованному дизайну. Второстепенные действия собраны в меню «⋯» с клавиатурным управлением и сохранением черновика.

`/install` объясняет установку PWA на рабочий стол. Это устанавливаемое веб-приложение, сервер и интернет для операций нужны. Личные страницы и ответы API не кэшируются для офлайн-доступа; без сети сохранение блокируется, черновик остаётся. Старый автономный HTML/скриншоты в `docs` — снимки дизайна, не рабочая CRM.

## Проверки разработки

```sh
npm run typecheck
npm test -- --maxWorkers=1
npm run build
E2E_PRODUCTION=true npm run test:e2e
```

Playwright использует `/usr/bin/chromium` (или `CHROMIUM_PATH`), отдельную временную базу, тестовые аккаунты и порт 3100. Не запускайте build и браузерный сервер одновременно: оба используют `.next`. Тесты не требуют production-паролей и не отправляют настоящие уведомления.

Интеграционные тесты PostgreSQL включаются только отдельным локальным адресом `127.0.0.1:55439`:

```sh
KARVEN_PG_TEST_URL='postgresql://TEST_USER:TEST_PASSWORD@127.0.0.1:55439/postgres' npx vitest run tests/postgres.test.ts --maxWorkers=1
```

Проверяются миграции/установщик, права anon, несколько серверов, повторы, лимит сессий, резервирование и восстановление. Никогда не подставляйте сюда рабочую Supabase. Изменив схему, обновите установщик командой `npm run db:sql`.
