# Проверка обновления владельца и менеджеров

Проверки выполнены на изолированных тестовых базах, без production-реквизитов, реальных платежей и доставки Telegram.

- `npm run build` — production-сборка успешна, проверка TypeScript проходит.
- Полный Vitest: 21 файл, 136 проверок прошли; PostgreSQL-сценарии без явного тестового адреса пропускаются. После последних изменений повторены затронутые suites (касса, операции, карточки): 32 проверки прошли, включая новый отзыв ожидающей передачи отправителем.
- PostgreSQL 17: 20 проверок прошли. Проверены полный SQL-установщик с пустым search_path, приватная схема/RLS, конкурентные серверные экземпляры, повтор операций, лимит 15 сессий, резервирование/восстановление, переход 9→10 с сохранением мест/сумм и панель владельца со снимками отчётов.
- Playwright Chromium, production-сборка + временная PGlite: 26 сценариев прошли. Включены все прежние операционные сценарии, 8 мест, формы/черновики, PWA, отмена с отдельным фактическим возвратом, менеджеры/водитель, владелец, PDF/CSV, Telegram без реальной отправки.
- Playwright Chromium, PostgreSQL + `CRM_DEPLOYMENT=netlify`: ещё 6 сценариев прошли — резервные копии и архив, касса двух сотрудников, блокировка сессии, подмена скрытого серверного действия обеими ролями, устаревшая карточка, PDF/CSV и закрытые настройки Telegram.
- Мобильная страница отчётов просмотрена, горизонтального переполнения страницы нет. Кириллица PDF проверена встроенным шрифтом и чтением метаданных; транспорт отправки PDF заменён подставным в unit-тесте.
- `git diff --check` — без ошибок.

Найденные и устранённые дефекты при проверке:

1. Старый автоматический возврат при отмене заменён обязательством и отдельным подтверждённым возвратом; скрытый старый серверный путь удалён.
2. Расчёт отменённого рейса без водителя учитывает удержание, не только расходы.
3. Резервная копия PostgreSQL ошибочно отклонялась из-за порядка строк при отличающейся локали PGlite. Сравнение выполняется по нормализованным полным строкам, а не их порядку; проверка содержимого и чисел сохраняется.
4. Блокировка сотрудника могла запереть смену отправителя ожидающей передачей. Ожидающие передачи отклоняются с журналом; отправитель также может отозвать свою передачу до принятия.
5. Обновление данных могло незаметно обновить версию в скрытом поле старого черновика. Редактор открывает свой снимок при первом раскрытии, сохраняет черновик и проверяет исходную версию; конфликт показан пользователю.
6. Исходный рабочий журнал и документы исчезали бы при восстановлении. Оригиналы сохраняются в отдельной архивной схеме и доступны после очистки рабочих записей; перенос архива документирован отдельно.

Ограничения: это не проверка реального банка или production-бота; состояние Netlify после публикации требует проверки развёртывания. Отчёт управленческий, правовую форму для налоговых органов нужно определить по стране/режиму/модели работы. Привилегированный администратор PostgreSQL может изменять архив; SHA-256 — контроль целостности, не электронная подпись. Бесплатные лимиты внешних сервисов сохраняются.
