# Обновление интерфейса KARVEN

Интерфейс перенесён в общий стиль согласованных макетов: тёмная навигация, светлый фон, белые панели, синие основные действия, зелёные статусы и янтарный остаток оплаты.

## Страницы

- «Клиенты»: поиск по имени/телефону, фильтры предстоящих поездок и задолженностей, аватары, количество заказов, ближайшая либо последняя поездка, долги отдельно по валютам, переход в карточку и новая бронь. Постоянным отмечается клиент с тремя завершёнными подтверждёнными заказами. Добавление контакта доступно до первого бронирования; совпадение нормализованного телефона не перезаписывает существующее имя.
- «Финансы»: журнал оплат, возвратов, расходов и выплат; фильтры периода в часовом поясе Бишкека, поиск, тип операции, CSV; отдельные вкладки долгов и расчётов с водителями. Подробные операции рейса сохранены под журналом. Суммы разных валют не объединяются. Сводка расходов включает расходы водителя, поэтому её нельзя считать остатком кассы; кассовый итог остаётся в подробном расчёте рейса.
- «Бронирования»: карточки с контактами, маршрутом, финансовым итогом, адресами, пассажирами, отметками посадки и всеми доступными по роли действиями. Кнопка оплаты раскрывает рабочую форму.
- «Новая бронь»: двухколоночные группы полей, полное название выбранного маршрута, свободные места, управление количеством пассажиров, заказчик и пассажиры, адреса, багаж, стоимость, предоплата и остаток. На узком экране поля адаптируются.
- Общие стили применены также к диспетчерской, водителям, автомобилям, задачам, отчётам, настройкам, диалогам и формам. Права ролей сохранены.

Верхние общие KPI остаются только в обзоре и диспетчерской. В клиентах и финансах вместо них показаны реальные дела. Пустое состояние не заполняется вымышленными клиентами или операциями.

## Проверка

Команды:

```sh
npm run typecheck
CRM_DEPLOYMENT=netlify npm run build
npm test -- --maxWorkers=1 --testTimeout=30000 --hookTimeout=60000
E2E_PRODUCTION=true npm run test:e2e
```

Браузерные проверки запускаются с отдельной временной тестовой базой, без подключения к рабочей Supabase. Дополнены сценарии финансового журнала, фильтров клиентов, CSV, перехода к оплате, добавления клиента без брони и размеров 390 / 768 / 1280 пикселей.

Обновление не требует миграции базы или новых переменных окружения. Контент и количество строк зависят от реальных данных; браузерные поля дат и выпадающие списки используют нативные элементы ОС.

Результат проверки: production-сборка и TypeScript успешны; 115 модульных тестов пройдены (15 проверок отдельного PostgreSQL пропущены без тестового сервера); 22 браузерных сценария пройдены. Дополнительно проверены все 9 разделов на ширине 390, 768 и 1280 пикселей без горизонтального переполнения страницы.
