# Аудит рейсов, вместимости и форм

Дата: 8 ноября 2026 года.

Проверены создание рейса, сохранение числа мест после перезагрузки, назначение автомобиля, изменение вместимости, брони всей машины, защита уже забронированных мест, ошибки и повторное исправление форм. Проверки выполнялись на отдельных тестовых базах PGlite и PostgreSQL.

## Результаты

| Сценарий | Найденное поведение | Исправление |
| --- | --- | --- |
| Создание рейса на 8 мест без автомобиля | Воспроизведение сохраняет 8 мест и после перезагрузки. Автоматическое превращение такого нового рейса в 4-местный в тесте не воспроизвелось. | Добавлена браузерная регрессия: таблица и схема мест показывают 8. |
| Назначение 4-местной машины на 8-местный рейс | Сервер молча заменял вместимость рейса вместимостью автомобиля. | Форма показывает переход 8 → 4 и требует отдельного подтверждения. Сервер проверяет подтверждение по фактическим прежней вместимости, машине и её текущей вместимости. |
| Машина или рейс изменились после открытия формы | Показанные в открытой форме значения могут устареть до сохранения. | Устаревшее подтверждение отклоняется, исходный рейс остаётся без изменений. В аудит назначения записываются прежнее и новое число мест. |
| Ошибка сохранения формы | React сбрасывал поля даже при возврате ошибки как результата действия. В браузере воспроизведено стирание даты рейса и сброс введённых 8 мест автомобиля к 4. | Форма отправляется явно через переход React; черновик сбрасывается только после успешного сохранения. Ошибка сохраняет введённые значения для исправления. |
| Редактирование уже сохранённой формы | Сообщение «Сохранено» оставалось видимым после изменения полей. | Старый результат скрывается при редактировании и во время нового сохранения. |
| Выбор рейса и вкладок | Локальные изменения URL запускали повторный серверный запрос и чтение данных страницы. | URL обновляется через History API без загрузки страницы; для свежих серверных данных добавлена кнопка «Обновить данные». В браузере проверено отсутствие GET-запросов при локальной навигации и наличие запроса при явном обновлении. |
| Повторное назначение | Сброс формы и локальные значения могли расходиться с актуальными данными рейса. | Назначение не сбрасывается после сохранения; выбранные ресурсы и окончание синхронизируются с сохранёнными данными. |

Машина на четыре места не может безопасно обслуживать восемь пассажиров. Поэтому приложение не сохраняет фиктивные восемь мест поверх физической вместимости: изменение требует подтверждения, а уже имеющиеся брони и число пассажиров проверяются независимо от него. Для сохранения восьми мест следует назначить автомобиль соответствующей вместимости.

## Проверки

- Общий набор: 128 автоматических тестов, включая PostgreSQL, конкурирующие брони, оплаты, роли, копии и ограничения соединений.
- Добавлены браузерные сценарии создания 8-местного рейса, исправления ошибки без повторного ввода даты, подтверждения 8 → 4, сохранения выбранных ресурсов и восстановления черновика автомобиля с 8 местами.
- Полный браузерный набор на PostgreSQL включает 17 сценариев: прежние проверки финансов, восстановления копий и ролей, а также пять новых регрессий аудита.

Изменение структуры базы не требуется. Уже существующие рейсы и их вместимость автоматически не переписываются. Этот отчёт относится к проверенным сценариям кода; реальные записи проекта Supabase в ходе этих тестов не изменялись.
