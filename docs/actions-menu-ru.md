# Основные действия и меню ⋯

На виду остаются создание брони, телефон клиента, получение оплаты, контакты пассажиров и отметки посадки. Поиск и фильтры не спрятаны.

Дополнительные операции собраны по месту работы:

- Бронь: изменение карточки, перенос, число пассажиров, история. Возврат и отмена выделены отдельной группой. Отмена неоплаченной брони требует отметки подтверждения; финансовые формы и ограничения ролей сохранены.
- Рейс: назначение/замена ресурсов, завершение и отмена. Быстрые ссылки контроля рейса раскрывают нужную операцию.
- Клиент: создание задачи и добавление заметки. Повторная бронь остаётся на виду.
- Финансы: экспорт CSV; получение оплаты и добавление расхода остаются основными действиями.

Меню использует нативный HTML popover: отображается поверх таблиц и диалогов, закрывается по клику снаружи и Escape. Форма остаётся смонтированной: закрытие меню не очищает черновик. После успешного сохранения меню закрывается автоматически; ошибка оставляет его открытым. Кнопка имеет доступное название и состояние раскрытия. При открытии меню координаты учитывают ширину и высоту экрана; длинные формы прокручиваются внутри панели.

Проверки: `npm run typecheck`, production-сборка и `E2E_PRODUCTION=true npm run test:e2e`. Сценарии обновлены под действия через меню. Отдельно проверяются клавиатура, возврат фокуса, закрытие меню внутри диалога рейса, сохранение черновика и размещение на экране шириной 390 пикселей.

Проверка завершена: TypeScript и production-сборка успешны. Проверены все 23 браузерных сценария: 22 прошли в общем прогоне, сценарий повторного назначения прошёл отдельно после обновления шага открытия меню в тесте. Бизнес-логика и схема базы не менялись.
